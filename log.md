# Log

**Time:** HUMAN ~2 h (reading, decisions, review). AI ~1.7 h, a rough estimate: Claude Code with Opus as the main session; about 20 Sonnet subagent runs of the recap skill; 2 reviewer subagents (a fact-check and one playing the hiring side); 1 session that wrote the transcript-cut fix from my instructions; about 30 `claude -p` runs inside `extra/recap.py`.

**First instruction** (the brief that opened this Claude Code session; my main session wrote it from my request, translated from Russian): "Help me do the Ironside Biz Ops case study. Read the instructions and the data, explain the task, what to submit and the deadline, and plan the solution with me. They look at how I approach the problem, direct AI and validate its work, so the solution should show the process: how the model was given tasks and how its outputs were checked (against the data, by hand, with explicit assumptions)."

**Setup:** Claude Code on the whole folder. Any number goes into the answers only after a script prints it (`analysis/pod_numbers.py`). Each skill rerun is a separate subagent that sees only its own copy of the brain, the skill and the transcript. A separate reviewer subagent with no context fact-checks every file against the raw data.

**What it got wrong:**
1. **The dashboard check said East was fine.** The first version of `pod_numbers.py` compared only the counts with `adoption.csv`, so it printed "ok" for East even though its own share column said 70% and the dashboard said 75%. I caught it by reading the output table row by row. Fix: the check itself, it now compares the share separately. That's how the East denominator bug showed up (B1).
2. **The checker failed good recaps.** The first `check_recap.py` flagged "within 48 hours" in the approved 3 Sep recap, and "30-day GMV" in mine, as typed performance numbers. I caught it because I ran it on the recaps the brain already accepts before trusting it on new ones. Fix: the check (periods aren't figures), not the recaps.
3. **The recap agent made up owners and dates.** With the old skill, 3 of 3 fresh runs turned "someone should look at the size chart" into an action item for Lena with "TBD" or a guessed date. Caught by the checker, then confirmed by reading all 6 outputs. Fix: the instruction, the skill now says to make it an open question. After the fix, 0 of 9 runs on the same transcript did it, and 0 of 4 on two calls the skill wasn't tuned on.
4. **The same mistake in my own A1 recap.** The main session made Marcus the owner of "samples go out Thursday", and nobody named him on the call (the 24 Sep call suggests Jess ships). The checker passed it, because it only checks that an owner exists. The reviewer subagent caught it, and it also caught a Flags line in that recap that hinted at what was held back. Fix: the output (moved to Open questions), plus a stated limit in `extra/README.md`. Lesson: the checks catch format, and a second reader catches meaning.
5. **A failure only the held-out calls showed.** Both runs on call-1 said the weekly affiliate figures are in the sheet. They aren't. I caught it by reading the outputs, because the checker passed both. Not fixed in the skill on purpose, so the held-out calls stay a test. Fixed in the checker instead: it now compares sheet claims with the sheet's columns.
6. **My own sandbox broke the agent's writes.** In `recap.py`, 2 early runs wrote no recap (one was in a first batch I discarded, so the kept logs show 1): the temp folder sits under `/var`, which on macOS is a symlink, and the write permission didn't match the real path. The gate held both back ("expected exactly one new recap"), so nothing wrong was posted. Fixed in the code with an absolute real path: every run since wrote its recap.
7. **A cause I stated without checking.** The first ticket said the 45-minute floor "looks like a queue or export wait". When asked where that came from, I tested the queue part: latency doesn't rise when several calls end together, so the data contradicts it. Fixed the output (the ticket now says only what the data shows: ~30 s per recap in our runs, so the time is likely outside the model), and the check now lives in `analysis/pod_numbers.py`.
8. **The cut failed open.** A reviewer playing the hiring side showed that a leave marker in another format (`[Dana Reyes dropped off]`) cut nothing and the leak check missed it too, because both parsed the transcript the same way. I decided the rule: when in doubt, hold the recap for a person. My first wording ("only `left the call` means leaving, otherwise the client stayed") still let `dropped off` through, because every transcript ends with `[Recording ended]`. Caught by swapping the marker in a real transcript. Fixed in the instruction: any bracketed line that isn't in `extra/system-lines.json` escalates, so a new format reaches a person on its first call and gets added to the file. One function now decides for both the cut and the check, with 18 tests in `extra/test_cut.py`.
