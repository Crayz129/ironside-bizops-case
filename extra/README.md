**What:** `recap.py` recaps one call end to end and enforces the brain's hard rules in code: it cuts the transcript when the client leaves, runs a fresh `claude -p` session on a temp copy of the brain, then posts the result only if exactly one new recap was written and `check_recap.py` passes. Picked because the bad recap was a pipeline failure, and this is the pipeline I'd want.
**Run:** `python3 extra/recap.py inbox/call-1.md --brain extra/brain-at-start --runs recap-runs --posted recap-runs/posted` (needs the `claude` CLI), or check one file: `python3 extra/check_recap.py RECAP.md --transcript CALL.md`.
**Measured:** checker on 26 recaps labeled by hand catches 9/9 bad, 1/17 false alarms (`python3 extra/eval_checker.py`). The command ran 28 times, median 27 s and $0.10 to $0.20 per recap, and every run is logged in `recap-runs*/` (`c2-before-after.md`).
**Limits:** if it can't tell where the client left (an unknown bracketed line, no client in the attendee list, a shared first name), it holds the recap for a person; known lines live in `system-lines.json`, tested by `python3 extra/test_cut.py`. The other checks are regexes: they see that an owner exists, not that they committed; a number on a line with "target" or "goal" gets through, and so does a paraphrase of post-call talk. The sheet rule was written after seeing the failures it catches.
